# 小组会会议总结 · 交稿模板

复制下方模板，保存为 `YYYY-MM-DD-会议主题.md`。方括号内替换成实际内容；按会议情况删去空的可选项。日期填写会议举行日，实验结果按原材料保留单位、条件和基线。

```markdown
# [会议主题]

- 会议日期：[YYYY-MM-DD]
- 主讲人：[姓名]
- 会议类型：[如论文分享、方案讨论、阶段汇报]
- 研究主题：[如具身 RL、资源调度]
- 一句话摘要：[研究了什么问题，本次汇报或讨论得出了什么主要认识]
- 依据材料：[原稿文件名；论文标题、版本或链接；相关页码或图号]

## 核心思想

[用一段话交代问题。随后用 1–3 段写清方法、起作用的原因及适用条件。]

## 结果与证据（有实验或数据时填写）

- [论文结果 / 组内实测] 在[模型、任务、设备及数量]上，相对[基线]，[指标及单位]从[原值]变为[新值]，或变化[百分比及方向]。[出处，如图号或页码]
- 图：[图的含义]。来源：[材料、版本、图号或页码]。建议图注：[读者应看哪两项、能由图得出什么结论]。

## 会议讨论与下一步

- [建议或问题]　提出人：[原稿中有署名时填写，否则写“会议讨论”]。
- [准备怎样验证]　比较对象：[基线]；观察指标：[指标]；负责人或时间：[会上已约定时填写]。

## 反馈与回复（有明确记录时填写）

- 反馈：[意见及提出人，按原稿填写]。
- 回复或安排：[已完成的动作或待办事项，写清当前状态]。
```

**交稿示例。** “在 Qwen2.5-7B、32 张 GPU 的 PPO 配置下，空间流水相对时间复用使 rollout 耗时增加 39.3%，但完整迭代因阶段重叠而缩短。”这一句交代了配置、比较对象和两种不同的时间指标。[查看第 06 期成稿](https://haodongwang01.github.io/group_meeting/meetings/2026-11-19.html)

## 维护者发布步骤

1. 对照原稿核实会议日期、主讲人及署名。原稿有疑点时，记录原表述、核对依据和最终口径到 `SOURCES.md`。论文结果、组内实测和待验证方向分别标明。
2. Markdown 用于交稿。发布时将正文整理成 `content/YYYY-MM-DD.html`，沿用相邻期的标题层级、章节锚点和可展开的补充图区；在 `content/meetings.json` 追加唯一期号并按日期倒序排列。摘要、主讲人、主题标签和封面要与正文对应。
3. 将正文引用的图片放到 `dist/assets/images/`，文件名包含日期，写好图注、来源和替代文本。Word、PPT 等原材料保存在本地。同步维护网站来源页和归档说明。
4. 运行 `python scripts/build.py` 和 `python scripts/check.py`。发布前打开首页、详情页和上一期，检查中文标题、数字单位、目录跳转、图片放大及前后期链接；推送后查看 GitHub Pages 的线上校验结果。
